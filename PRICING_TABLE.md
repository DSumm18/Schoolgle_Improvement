## Trial Module Flow

1. **School requests trial** of specific module(s)
2. **Set up in database**: `pricing_type = 'trial'`, `trial_end_date = 30 days`
3. **School gets free access** until trial end date
4. **Before trial ends**: Offer conversion discount (TRIAL10 or TRIAL15)
5. **If they convert**: Apply discount, set `trial_converted = true`
6. **If they don't convert**: Access revoked, follow up in 3 months

## Pricing FAQ

### Can we change module pricing?
**Yes**. Add new row to `module_pricing` with new `effective_from` date. Old prices remain for historical data.

### Can we offer time-limited promotions?
**Yes**. Create discount code with `valid_until` date and/or `max_uses` limit.

### Can we give custom pricing to a specific school?
**Yes**. Use `organization_pricing` table to set `custom_price` or `discount_percent` for that org.

### Can we bundle modules for a discount?
**Yes**. Either create a discount code or set `pricing_type = 'bespoke'` with custom total price.

### How do we track discount effectiveness?
**Use** `discount_usage` **table**. Every discount application is tracked with organization, amount, date, and referrer if applicable.

### What happens when a trial ends?
**System checks** `trial_end_date`. If not converted, access is automatically revoked. Follow-up email sent with TRIAL15 code.
